# 服務中心公告推播更新說明

## 本次修改

1. `/start` 不再先送最新公告。
   - 現在 `/start` 只送服務中心主頁按鈕。
   - 公告內容只放在「公告事項」按鈕內查看。

2. 公告會存進 DB。
   - table：`service_center_announcements`
   - 最新公告仍顯示在公告事項最上面。

3. 新增主動推播。
   - table：`service_center_subscribers`
   - 使用者只要曾經私訊或操作服務中心 bot，就會記錄 chat_id。
   - Telegram bot 只能主動傳訊息給曾經開始過對話的使用者或曾經互動過的 chat。

4. 每天下午五點推新公告。
   - 時區：Asia/Taipei
   - 每天 17:00 後檢查一次。
   - 若有 `push_enabled = TRUE` 且 `pushed_at IS NULL` 的公告，就主動推播。
   - 推播流程跑完後會把該公告設為 `push_enabled = FALSE` 並寫入 `pushed_at`，所以同一則公告不會在未來重複推給新加入的 chat。
   - table：`service_center_announcement_deliveries`
   - unique：`announcement_id + chat_id`，避免 Render 重啟或多 worker 重複推同一則公告。

## 本次預設公告

標籤：功能更新
標題：圖片與貼圖輸入更新
內容：

1. 新增圖片訊息支援：使用者直接傳圖片時，系統會先解析圖片內容，再交回聊天流程自然回覆。
2. 新增靜態貼圖支援：Telegram 靜態貼圖會被解析成可理解的文字內容，再由 AI 接續回覆。
3. 新增未支援媒體防呆：語音、音訊、影片、GIF、動態貼圖、影片貼圖、文件、位置等目前尚未支援的輸入，會回覆提示，不會再完全沒反應。

## 新增 table

```sql
service_center_subscribers
service_center_announcement_deliveries
service_center_scheduler_state
```

## 管理員新增公告

```text
/announce 功能更新｜標題｜內容
```

新增後會先出現在公告事項，下一次台灣時間下午五點主動推播一次。
